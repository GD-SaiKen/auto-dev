# 怎么提 Issue

打开 Issue 就会自动开始处理。写成一句话也可以。

下面两种写法只是便于少来回，缺哪一行都照收。

## 需求

- **要办的事**：现在什么问题，或要什么结果
- **做完的样子**：怎样能看出来办完了
- **补充**：截图、例子、链接，有就附上

## 缺陷

- **哪里**：哪个画面、哪一步
- **实际**：现在出现了什么
- **期望**：本来应该怎样
- **补充**：报错原文、截图，有就附上

WorkBuddy、Codex、DeepSeek harness、Hermes 或其他工具，把上面这段当作说明即可：能整理成这几行就整理；对方只说了一句话，就按原话开 Issue，不要追问到齐再交。

接着写开发方案或改代码时，改读 [写方案和代码](写方案和代码.md)。
