# 怎么提 Issue

新建 Issue **不会**自动改代码。它是 SDD 闭环的起点：规格 → 规格评审 → 实施计划 → 计划评审，最后在 Actions **手动**运行 `auto-develop`。

写成一句话也可以。下面两种结构便于少来回，缺哪一行都照收。

## 需求

- **要办的事**：现在什么问题，或要什么结果
- **做完的样子**：怎样能看出来办完了
- **补充**：截图、例子、链接，有就附上

## 缺陷

- **哪里**：哪个画面、哪一步
- **实际**：现在出现了什么
- **期望**：本来应该怎样
- **补充**：报错原文、截图，有就附上

WorkBuddy、Codex、DeepSeek harness、Hermes 或其他工具：能整理成上面几行就整理；用户只说一句话就原话开 Issue，不要追问到齐再交。

接着写 **docs/SDD** 或改代码时，读 [写方案和代码](写方案和代码.md) 与 [流水线全流程](流水线全流程.md)。
